# BrewLog 앱형 프론트엔드 개편 계획 v1.0

## 1. 목적

현재 BrewLog 프론트엔드는 기능 확인과 데이터 조회에는 충분하지만, 사용자가 매일 쓰는 앱처럼 느껴지기에는 정보량이 많고 화면 목적이 흐릿하다.

이 문서는 BrewLog를 다음 방향으로 개편하기 위한 기준 문서이다.

- 흰색 배경과 갈색 포인트를 중심으로 한 차분한 앱 UI
- 목록보다 사용자의 다음 행동이 먼저 보이는 UX
- 원두, 브루잉, 카페 기록을 각각 다른 목적의 기록으로 명확히 분리
- 모바일에서 먼저 자연스럽고, 데스크톱에서는 넓은 앱처럼 보이는 반응형 구조
- Thymeleaf를 유지하되, 복잡한 인터랙션은 Vue3 또는 React로 분리할 수 있는 구조

## 2. 제품 관점

BrewLog는 커피 데이터를 관리하는 도구가 아니라, 사용자가 마신 커피 경험을 빠르게 남기고 다시 떠올리는 개인 기록 앱이다.

핵심 문장:

```text
내가 가진 원두와 마신 커피를 빠르게 기록하고, 나중에 맛과 장소를 감각적으로 다시 보는 앱
```

## 3. 사용자 순간과 화면 역할

| 순간 | 사용자의 생각 | 화면이 도와야 하는 일 |
|---|---|---|
| 새 원두를 샀다 | 사진이나 정보로 빨리 등록하고 싶다 | OCR/LLM 로딩을 명확히 보여주고, 확인 후 저장하게 한다 |
| 커피를 내렸다 | 레시피와 맛만 빠르게 남기고 싶다 | 원두 선택, 푸어링 그래프, 맛 기록을 단계적으로 진행한다 |
| 카페에서 필터커피를 마셨다 | 카페와 원두 느낌만 따로 남기고 싶다 | 브루잉 기록과 섞지 않고 카페 필터 기록으로 저장한다 |
| 원두가 얼마나 남았는지 본다 | 지금 마실 수 있는 원두가 뭔지 알고 싶다 | 보유중 원두를 가장 먼저, 작은 카드로 보여준다 |
| 예전 기록을 본다 | 이 원두가 어땠는지 떠올리고 싶다 | 향미 그라데이션, 메모, 브루잉 이력을 먼저 보여준다 |
| 방문한 카페를 본다 | 어디에서 마셨는지 지도에서 보고 싶다 | 지도와 카페 목록을 함께 보여주고 핀 선택으로 정보를 확인한다 |

## 4. 디자인 원칙

### 4.1 앱처럼 보이게 하는 기준

- 첫 화면에 모든 데이터를 펼치지 않는다.
- 목록 카드는 상세 정보가 아니라 진입점이다.
- 주요 액션은 한 화면에 1개만 강하게 둔다.
- 모바일 화면에서 한 손으로 누르기 쉬운 위치에 하단 네비와 빠른 추가 버튼을 둔다.
- 카드 안에 카드가 들어가는 구조를 만들지 않는다.
- 설명 문구보다 상태, 숫자, 행동 버튼으로 흐름을 만든다.
- 지도, 그래프, 향미 그라데이션처럼 BrewLog만의 시각 요소를 유지한다.

### 4.2 색상 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| Background | `#FFFFFF` | 기본 화면 배경 |
| Surface | `#FFFFFF` | 카드, 입력 영역 |
| Surface Subtle | `#FAF8F6` | 아주 약한 보조 영역 |
| Text Primary | `#2A211D` | 제목, 주요 텍스트 |
| Text Secondary | `#7A6B63` | 설명, 보조 텍스트 |
| Brown Primary | `#6F3F28` | 주요 버튼, 활성 상태 |
| Brown Pressed | `#54301F` | 버튼 눌림, 강조 |
| Brown Soft | `#F6F1EE` | 칩, 선택 전 배경 |
| Line | `#EEE6E1` | 구분선, 카드 라인 |
| Danger | `#B13A2E` | 삭제, 위험 액션 |

### 4.3 타이포그래피 원칙

- 데스크톱의 큰 제목은 줄이고, 모바일 앱 화면명처럼 단단하게 쓴다.
- 목록 카드 제목은 2줄까지 허용하고, 그 외 텍스트는 최소화한다.
- 버튼 텍스트는 짧게 유지한다.
- 설명 문구는 페이지 상단에 길게 두지 않고 필요한 위치에만 둔다.

## 5. 전체 내비게이션 구조

### 5.1 모바일 우선 구조

```text
상단: 로고 / 현재 화면명 또는 최소 브랜드
하단: 홈 / 원두 / 브루잉 / 카페 / 지도
우하단: 빠른 추가 버튼
```

### 5.2 데스크톱 구조

```text
상단: 로고 / 주요 메뉴 / 빠른 액션
본문: 최대 폭을 제한한 앱형 레이아웃
지도 화면: 필요할 때만 넓게 사용
```

### 5.3 빠른 추가 메뉴

| 메뉴 | 이동 | 목적 |
|---|---|---|
| 새 원두 | `/coffee-beans/new` | 구매한 원두 등록 |
| 브루잉 | `/brew-records/new` | 직접 내린 커피 기록 |
| 카페 필터 | `/cafe-filter-coffees/new` | 카페에서 마신 필터커피 기록 |

## 6. 핵심 사용자 플로우

### 6.1 보유 원두 확인 후 브루잉 기록

```text
홈
→ 보유중 원두 요약 확인
→ 원두 카드 선택
→ 원두 상세
→ 브루잉 기록하기
→ 원두 선택은 자동 채움
→ 레시피 입력
→ 맛/느낌/메모 입력
→ 저장
→ 브루잉 상세 또는 원두 상세로 복귀
```

기준:

- 원두 목록 카드에는 향미 그라데이션, 이름, 남은 g만 보여준다.
- 원두 상세에서는 최근 브루잉 기록과 남은 g가 먼저 보여야 한다.
- 브루잉 기록 저장 후 원두 무게 차감 결과가 명확해야 한다.

### 6.2 새 원두 등록

```text
빠른 추가
→ 새 원두
→ 카드 이미지 업로드 또는 수동 입력
→ OCR/LLM 분석 중 로딩
→ 자동 채움 결과 확인
→ 구매처 검색 또는 지도 선택
→ 향미 노트 확인
→ 저장 중 로딩
→ 원두 상세
```

기준:

- OCR/LLM이 호출되는 동안 `원두 정보를 불러오는 중입니다` 또는 `원두를 저장중입니다`를 명확히 띄운다.
- 사용자는 자동 채움 결과를 저장 전에 수정할 수 있어야 한다.
- 구매처는 기존 장소와 중복 저장되지 않아야 한다.
- 기존 향미 노트에 없는 값은 저장 중 색상 추천 후 DB에 저장된다.

### 6.3 브루잉 기록 작성

```text
빠른 추가
→ 브루잉
→ 원두 선택
→ 추출 조건 입력
→ 푸어링 그래프 편집
→ 만족도/맛 프로파일
→ 느낌/메모
→ 저장
```

기준:

- 단계는 유지하되, 화면 하단 버튼은 이전/다음 화살표 중심으로 둔다.
- 저장 버튼은 마지막 단계에서만 보인다.
- 푸어링 그래프는 x축 시간, y축 누적 물량을 보여준다.
- 종료 시간은 1초 단위로 입력 가능해야 한다.
- 각 포인트의 시간과 물량을 그래프에서 확인할 수 있어야 한다.

### 6.4 카페 필터커피 기록

```text
빠른 추가
→ 카페 필터
→ 카페 검색 또는 기존 카페 선택
→ 원두 정보 입력
→ 핫/아이스 선택
→ 향미/느낌/메모 입력
→ 선택적으로 레시피 기록
→ 저장
→ 카페 필터 상세
```

기준:

- 카페 필터 기록은 브루잉 기록과 중복 저장되지 않는다.
- 카페별 필터링이 가능해야 한다.
- 같은 카페는 카카오 place id, 이름, 주소, 좌표를 기준으로 중복 생성되지 않아야 한다.
- 카페에서 마신 커피는 원두 카드로 자동 채움할 수 있다.

### 6.5 지도에서 회상하기

```text
지도
→ 지역 선택
→ 방문 카페 목록 확인
→ 지도 핀 선택
→ 카페 정보 표시
→ 카페 필터 기록으로 이동
```

기준:

- 지도는 좌우 여백이 과하지 않게 반응형으로 맞춘다.
- 모바일에서는 정보 패널을 사이드바가 아니라 바텀시트처럼 보이게 한다.
- 핀 위치는 실제 좌표와 지도 투영 위치가 일치해야 한다.

## 7. 화면별 개편 방향

### 7.1 홈

우선순위:

1. 오늘 바로 할 수 있는 액션
2. 보유 원두 요약
3. 원산지 지도
4. 최근 기록

권장 구조:

```text
[상단 인사]
오늘 어떤 커피를 마실까요?

[빠른 액션]
브루잉 기록 / 새 원두 / 카페 필터

[보유 원두 미리보기]
작은 카드 2~4개

[원산지 지도]
경험한 산지 시각화

[최근 기록]
브루잉, 카페 필터 혼합 타임라인
```

### 7.2 원두 목록

카드 표시 정보:

- 향미 그라데이션
- 원두 이름
- 남은 g

목록 상단:

- 보유중 / 모두 소진 / 카페 시식 탭
- 검색
- 새 원두 버튼

모바일 기준:

- 카드 1개 높이를 낮춰 한 화면에 최소 3개 이상 보이게 한다.
- 카드 내부 텍스트는 2줄까지만 허용한다.

### 7.3 원두 상세

우선순위:

1. 향미 노트 그라데이션
2. 원두 이름
3. 남은 g와 상태
4. 주요 액션: 브루잉 기록하기
5. 최근 브루잉 기록
6. 세부정보
7. 구매처 지도

### 7.4 브루잉 목록

카드 표시 정보:

- 날짜
- 원두 이름
- 만족도
- 추출 타입
- 짧은 메모

브루잉 목록은 레시피 목록이 아니라 마신 경험의 타임라인처럼 보이게 한다.

### 7.5 브루잉 상세

우선순위:

1. 원두 이름과 날짜
2. 만족도
3. 푸어링 그래프
4. 맛 프로파일
5. 느낌/메모
6. 레시피 수치

### 7.6 카페 필터 목록

상단 구조:

```text
전체 / 카페별 필터 칩 / 검색
```

카드 표시 정보:

- 카페 이름
- 원두 이름
- 마신 날
- 핫/아이스
- 만족도
- 향미 그라데이션

### 7.7 카페 지도

데스크톱:

```text
지도 2/3 + 카페 패널 1/3
```

모바일:

```text
지도 전체
하단 바텀시트로 선택 지역/카페 정보
```

### 7.8 등록/수정 폼

공통 원칙:

- 한 단계에는 한 목적만 둔다.
- 다음 단계에 필요한 값만 필수 검증한다.
- 이전/다음은 화살표 버튼으로 이동한다.
- 저장은 마지막 단계에서만 표시한다.
- 취소는 페이지 제목 옆 또는 상단 우측에 둔다.

## 9. 구현 단계와 커밋 단위

### Phase 0. 기준 문서와 구현 범위 확정

커밋 단위:

- `프론트 앱형 개편 계획 문서화`

작업:

- 이 문서를 추가한다.
- 기존 `brewlog_frontend_design_v1.md`는 참고 문서로 유지한다.
- 앞으로 UI 개편 시 이 문서를 우선 기준으로 사용한다.

검증:

- 문서 링크가 인덱스에 포함되어 있는지 확인한다.

### Phase 1. 공통 디자인 토큰 정리

커밋 단위:

- `앱형 디자인 토큰 정리`

작업:

- `main.css`의 색상 토큰을 흰색 배경 중심으로 정리한다.
- 카드, 버튼, 입력창, 칩, 그림자, 라운드 값을 통일한다.
- 베이지 배경이 강하게 보이는 영역을 흰색 또는 아주 약한 보조 배경으로 바꾼다.

검증:

- 홈, 원두 목록, 브루잉 폼, 카페 지도에서 색이 한쪽으로 과하게 치우치지 않는지 확인한다.
- 모바일 390px, 데스크톱 1440px에서 텍스트 겹침이 없는지 확인한다.

### Phase 2. 앱 쉘 정리

커밋 단위:

- `앱형 헤더와 하단 네비 정리`

작업:

- 모바일 헤더는 로고와 최소 정보만 남긴다.
- 모바일 하단 네비는 홈/원두/브루잉/카페/지도 5개를 안정적으로 배치한다.
- 빠른 추가 버튼 위치와 메뉴를 정리한다.
- 데스크톱 헤더는 현재 구조를 유지하되 폭과 여백을 앱 컨테이너와 맞춘다.

검증:

- 모바일에서 헤더가 가로로 넘치지 않는지 확인한다.
- 하단 네비가 본문 버튼이나 지도 패널을 가리지 않는지 확인한다.

### Phase 3. 홈 개편

커밋 단위:

- `홈 화면 앱 대시보드 개편`

작업:

- 홈 상단에 빠른 액션을 배치한다.
- 보유 원두 미리보기 섹션을 추가한다.
- 기존 원산지 지도는 홈의 주요 시각 요소로 유지하되, 화면 첫 진입 시 과하게 크지 않도록 조정한다.
- 최근 기록 타임라인을 추가할 수 있는 구조를 만든다.

검증:

- 홈에서 새 원두, 브루잉, 카페 필터 기록으로 바로 이동되는지 확인한다.
- 모바일에서 첫 화면에 주요 액션이 보이는지 확인한다.

### Phase 4. 원두 목록 개편

커밋 단위:

- `원두 목록 앱 카드 개편`

작업:

- 보유중/모두 소진/카페 시식 탭을 더 작고 명확하게 정리한다.
- 원두 카드에는 향미 그라데이션, 이름, 남은 g만 유지한다.
- 검색과 새 원두 버튼을 모바일에서 자연스럽게 배치한다.
- 한 화면에 더 많은 카드가 보이도록 높이와 여백을 줄인다.

검증:

- 카드 클릭 시 상세로 이동한다.
- 모바일에서 카드가 최소 3개 이상 보이는지 확인한다.
- 소진된 원두의 남은 g 수정 후 보유중으로 다시 이동하는지 확인한다.

### Phase 5. 원두 상세 개편

커밋 단위:

- `원두 상세 회상형 레이아웃 개편`

작업:

- 향미 그라데이션과 원두 이름을 최상단에 둔다.
- 남은 g, 상태, 주요 액션을 요약 영역에 배치한다.
- 세부정보는 접거나 아래로 내린다.
- 구매처는 지도와 핀 중심으로 보여준다.

검증:

- 구매처 정보에서 좌표, 주소, 장소 링크가 과하게 노출되지 않는지 확인한다.
- 핀 클릭 시 구매처 정보가 보이는지 확인한다.

### Phase 6. 브루잉 목록/상세 개편

커밋 단위:

- `브루잉 기록 화면 개편`

작업:

- 브루잉 목록을 타임라인 카드처럼 정리한다.
- 상세에서는 푸어링 그래프를 중심 정보로 둔다.
- x축에 각 포인트 시간이 표시되도록 유지한다.
- 만족도, 맛 프로파일, 메모를 읽기 좋은 순서로 배치한다.

검증:

- 1초 단위 종료 시간이 저장되는지 확인한다.
- 저장 버튼이 마지막 단계에서만 동작하는지 확인한다.
- 그래프 포인트와 텍스트가 겹치지 않는지 확인한다.

### Phase 7. 카페 필터 화면 개편

커밋 단위:

- `카페 필터 기록 화면 개편`

작업:

- 카페별 필터 기능을 상단 칩 또는 셀렉트로 정리한다.
- 카페 필터 상세에서 브루잉 기록과 중복되는 느낌을 줄인다.
- 카페 검색, 기존 카페 선택, 지도 선택 흐름을 한 화면 안에서 자연스럽게 연결한다.

검증:

- 기존 카페를 다시 등록해도 중복 장소가 생성되지 않는지 확인한다.
- 카페별 필터가 정확히 적용되는지 확인한다.

### Phase 8. 지도 화면 개편

커밋 단위:

- `카페 지도 앱형 패널 개편`

작업:

- 데스크톱 지도와 패널 비율을 정리한다.
- 모바일 지도 정보 패널을 바텀시트처럼 변경한다.
- 핀 위치와 선택 지역 표시를 조정한다.

검증:

- 광주 등 특정 지역 선택 시 핀이 실제 위치에 가깝게 보이는지 확인한다.
- 화면 폭이 달라져도 좌우 여백이 과해지지 않는지 확인한다.

### Phase 9. 등록 폼 전체 정리

커밋 단위:

- `등록 폼 단계형 UX 정리`

작업:

- 원두 등록, 브루잉 등록, 카페 필터 등록의 단계형 UI를 같은 규칙으로 통일한다.
- 취소 버튼 위치를 페이지 제목 줄과 맞춘다.
- 이전/다음/저장 버튼 표시 규칙을 공통화한다.
- 저장 중 로딩 오버레이를 공통 컴포넌트처럼 사용한다.

검증:

- 필수값 검증이 단계별로 자연스럽게 동작하는지 확인한다.
- LLM 호출이 있는 저장에서 로딩 문구가 표시되는지 확인한다.

### Phase 10. 프론트 분리 검토

커밋 단위:

- `프론트 분리 전환 검토 문서 추가`

작업:

- Thymeleaf 유지가 어려운 화면을 정리한다.
- Vue3 또는 React로 분리할 후보 화면을 정한다.
- API 응답 DTO와 화면 상태 구조를 정리한다.

판단 기준:

- 단계형 폼 상태가 복잡해지는가
- 지도와 선택 패널 상태가 복잡해지는가
- OCR/LLM 로딩과 결과 수정 흐름이 복잡해지는가
- 같은 컴포넌트를 여러 화면에서 재사용해야 하는가

권장 방향:

- 단기: Thymeleaf + CSS + 필요한 JS 개선
- 중기: 복잡한 화면만 Vue3 island 형태로 도입
- 장기: Vue3 SPA + Spring Boot API 분리

## 10. 구현 우선순위

1. Phase 1: 공통 디자인 토큰 정리
2. Phase 2: 앱 쉘 정리
3. Phase 4: 원두 목록 개편
4. Phase 5: 원두 상세 개편
5. Phase 3: 홈 개편
6. Phase 6: 브루잉 목록/상세 개편
7. Phase 9: 등록 폼 전체 정리
8. Phase 7: 카페 필터 화면 개편
9. Phase 8: 지도 화면 개편
10. Phase 10: 프론트 분리 검토

원두 목록과 원두 상세를 홈보다 먼저 둘 수 있다. 사용자가 현재 가장 많이 피드백을 준 화면이 원두 흐름이고, 여기서 앱의 시각 언어를 먼저 안정화할 수 있기 때문이다.

## 11. 첫 구현 작업 정의

작업명:

```text
앱형 디자인 토큰과 원두 목록 1차 정리
```

포함 범위:

- `main.css` 색상 토큰을 흰색 배경 중심으로 정리
- 원두 목록 상단 여백과 제목 크기 축소
- 원두 탭/검색/카드 밀도 정리
- 모바일에서 원두 카드 3개 이상 보이도록 조정

제외 범위:

- 홈 구조 대개편
- Vue3/React 도입
- 백엔드 API 분리
- 지도 구조 변경
- 등록 폼 전체 리팩터링

완료 조건:

- 모바일 390px에서 원두 목록이 앱 화면처럼 보인다.
- 원두 카드가 정보 확인용 테이블처럼 보이지 않는다.
- 데스크톱에서도 카드가 과하게 넓거나 비어 보이지 않는다.
- 기존 기능 이동 경로가 유지된다.
